## Incident (2026-08-31): legacy `trg_push_acwr_alert` flooded the coach's phone during backfill

The 3.10 backfill (600 `daily_training_load` INSERTs across 5 athletes) fired a pre-existing, unrelated trigger — `trg_push_acwr_alert` (from `20260310100638_acwr_push_alert_trigger`) — which had no insert-side dedup and sent ~50 push notifications to the one affected coach (`albert9063@gmail.com`, the only real coach account among the backfilled athletes) within seconds. Not caused by this change's own alert system (`TRAINING_LOAD_ALERTS_ENABLED=false` was correctly respected throughout). Root cause: didn't check for existing triggers on `daily_training_load` before a bulk write.

Resolved same-day: trigger disabled immediately, then dropped per user decision (fully superseded by `training_load_alerts`' `acwr_zone` signal, which has real dedup/lifecycle/hysteresis). See `supabase/migrations/20260819147000_drop_legacy_acwr_push_trigger.sql` (+ `_rollback.sql`, restores the original buggy behavior — do not re-enable without adding an insert-side guard first).

**Lesson for any future bulk write to a table in this repo**: check `information_schema.triggers` for the target table first. This codebase has undocumented triggers same as it has undocumented tables/functions.
